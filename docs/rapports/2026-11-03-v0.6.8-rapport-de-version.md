## 1. Caméras de Québec 511 : la vidéo ne s'affiche plus au survol

**Ce que j'ai vérifié**

- Les données ouvertes des caméras n'ont pas changé : toujours 680 caméras, et la même adresse officielle par caméra
  (`…/Carte/Fenetres/FenetreVideo.html?id=…`, identique à celle du 2026-10-29).
- Notre code n'est pas en cause : le Service Worker ne touche qu'aux photos du MTMD, pas aux vidéos.
- Je n'ai pas pu tester la vidéo elle-même : depuis un serveur infonuagique, quebec511.info répond par la page
  Cloudflare « Attention Required! » (403). Les serveurs du MTMD font pareil (fiches APEX, OData,
  transports.gouv.qc.ca). Seul le WFS répond. Ce blocage vise les adresses de centres de données, pas toi.

**Mon avis**

- Un blocage personnel est peu probable : l'atlas ne demande une vidéo qu'au survol, comme la carte de Québec 511.
- Cause la plus probable : Québec 511 a durci sa protection et refuse maintenant ses vidéos quand une autre page les
  affiche. Je n'ai pas cherché à contourner cette protection : ce serait aller contre leur choix.

**Test d'une minute pour trancher (dans ton navigateur habituel)**

1. Ouvre la [carte de Québec 511](https://www.quebec511.info/fr/Carte/Default.aspx) et une caméra.
   Pas de vidéo là non plus ? Alors ton adresse IP ou ton navigateur est bloqué (attendre un jour ou changer de réseau).
2. Ouvre [la vidéo de la caméra Q5413](https://www.quebec511.info/Carte/Fenetres/camera.ashx?id=3998&format=mp4)
   directement dans un onglet. Elle joue ici mais pas dans l'atlas ? Alors Québec 511 refuse l'affichage hors de son
   site. On garde le lien et l'image fixe, sans vidéo intégrée.
3. Tu vois une page Cloudflare à l'étape 2 ? Même conclusion qu'à l'étape 1.

**Changements dans l'atlas**

- Le **clic** sur une caméra ouvre sa page officielle chez Québec 511 (adresse tirée des données ouvertes). Avant, il
  ouvrait la carte de Québec 511.
- Une vidéo qui ne démarre pas après 12 s passe au repli : image fixe, sinon message.
- Après **deux caméras refusées de suite**, la bulle le dit : « Québec 511 refuse sans doute l'affichage de ses
  vidéos hors de son site ».
- Écran tactile : deux liens, « Voir la caméra sur Québec 511 » et la carte.
- L'ETL signale dans son journal tout changement d'adresse des caméras dans les données ouvertes. Un tel changement
  voudrait dire que l'adresse des vidéos a pu changer aussi.

## 2. Repères kilométriques dans les fiches

- Source : jeu « Repère kilométrique » du MTMD (Données Québec, CC BY 4.0), WFS `ms:repere_km`. Il compte 14 000
  panneaux, dont 13 571 routiers ; les pistes cyclables, de quad et de motoneige sont écartées.
- Nouvelle ligne **« Repère km »** dans la section Localisation de la fiche, avec la source sous le texte. Exemples :
  - « Autoroute 40 : entre km 272 et km 273 (≈ km 272,3) »
  - « Route 172 : au km 18 »
  - « Autoroute 25 : à 1,0 km du km 3,3 (route franchie) »
- Résultat : **3 460 structures sur 11 701** ont un repère, dont 3 094 entre deux repères. Les panneaux couvrent surtout
  les autoroutes et une partie des routes numérotées (environ 110 routes). Les autres fiches n'ont pas la ligne.
- Règles :
  - On cherche d'abord sur la route portée : son n°, ou son nom pour une route locale.
  - Sinon, on prend la route franchie. C'est le cas d'un viaduc municipal au-dessus d'une autoroute.
  - Sur une chaussée séparée (« Autoroute 20 Est »), les panneaux du même sens passent d'abord.
  - Le repère retenu doit être à moins de 2,5 km.
  - Pour dire « entre deux repères », il faut deux repères voisins du même sens, et la structure doit être à moins de
    300 m de la droite qui les relie. Le km est alors estimé par interpolation.
  - Les bretelles n'ont pas de repère.
- Code : `etl/reperes.py`, lancé avec les couches → `data/reperes.js` (133 Ko). Ce fichier est chargé après
  l'affichage de la carte.

## 4. Extraction des données aujourd'hui, puis toutes les 2 semaines

**Constat** : les données de l'atlas datent du **2026-10-11**. Aucune extraction automatique n'existait dans le dépôt :
le plan de match prévoyait une GitHub Action aux 2 mois, jamais créée.

**Extraction d'aujourd'hui, faite en partie depuis le serveur**

- Rafraîchies le 2026-11-03 : caméras, repères kilométriques, réseau routier (RTSS), réseau ferroviaire et sondages
  géotechniques. Ces couches viennent du WFS, qui répond.
- Pas faisable d'ici : l'inventaire (structures, ICG, inspections), les débits, les villes, les ponts hors MTMD,
  la sismique, le dégel, Wikipédia et les habitats. Les serveurs refusent l'accès (403), ou ces couches ont besoin de la
  base locale. Les fichiers déjà publiés sont gardés tels quels.

**Extraction automatique toutes les 2 semaines (sur ton PC)**

- GitHub Actions ne peut pas faire ce travail : comme ce serveur, il utilise des adresses de centres de données, que le
  MTMD refuse. Il faut une connexion résidentielle.
- Nouveau dossier `outils/` :
  - `outils\planifier-extraction.cmd` : en double-cliquant dessus, on crée la tâche Windows « QuickerAtlas -
    extraction ». Elle tourne **toutes les 2 semaines, le mardi à 12 h 15, à partir d'aujourd'hui**. Le même
    double-clic lance **tout de suite** l'extraction d'aujourd'hui. Si le PC est éteint à l'heure prévue, elle tourne
    au rallumage.
  - `outils\extraction.ps1` (lancé par la tâche) :
    1. `git pull` sur main ;
    2. `python -m etl update` ;
    3. `python -m pytest` ;
    4. commit des seuls fichiers `data/` ;
    5. push.
    Si les tests échouent, rien n'est publié. Le journal est dans `data\raw\extraction-AAAA-MM-JJ.log`.
- **À faire de ton côté, une seule fois** : après ce push, `git pull` sur main dans ton dossier QuickerAtlas, puis
  double-clic sur `outils\planifier-extraction.cmd`.
- Si une ancienne tâche du projet existe dans le Planificateur, le script l'affiche avec la commande pour la retirer.
- Je n'ai pas pu lancer ces scripts PowerShell ici, faute de Windows : surveille la première exécution (journal
  ci-dessus).
